# 2026-08-09

## LLDAP Password Reset Fix (2026-08-09)

### Problem
- `user-invite.becklab.cloud` returned 401 for admin login despite correct password
- LLDAP's `force_ldap_user_pass_reset` set to `"always"` in `lldap_config.toml` but **not taking effect**
- Verbose config showed `force_ldap_user_pass_reset: False` despite TOML having `"always"`
- The root cause: the **TOML file value was silently ignored** by Figment merge
- Only setting via **env var** `LLDAP_FORCE_LDAP_USER_PASS_RESET=always` worked

### Root Cause Analysis
LLDAP v0.6.3 config loading uses Figment with merge order:
1. Default builder (`False`)
2. TOML file → merged into Figment
3. Env vars (`LLDAP_*`) → merged on top
4. CLI overrides (`inspect` only if `Some`)

The TOML value `force_ldap_user_pass_reset = "always"` was **not parsed correctly**. Suspected Figment `ignore_keys` or TOML duplicate key issue (there's a commented `# force_ldap_user_pass_reset = false` on line 89 and the real value on line 175).

### Fix Applied
1. Set `LLDAP_FORCE_LDAP_USER_PASS_RESET=always` via env var on `lldap` deployment
2. LLDAP correctly parsed `TrueFalseAlways::Always` from env var
3. `register_password()` ran on startup → stored new OPAQUE hash for `newpass123`
4. Verified `/auth/simple/login` accepts `newpass123` → returns JWT token
5. Verified user-invite can authenticate via LLDAP GraphQL API
6. Removed `force_ldap_user_pass_reset = always` from TOML and env var (reset to `false`)
7. Updated user-invite deployment: `LLDAP_ADMIN_PASS` → direct value `newpass123` (was secretKeyRef to old password)
8. Committed to GitOps: `e180111`

### Key Findings
- LLDAP `force_ldap_user_pass_reset` from **TOML file** may not parse correctly (possible Figment bug with enum deserialization)
- Setting via **env var** `LLDAP_FORCE_LDAP_USER_PASS_RESET` works reliably
- Both `/auth/simple/login` (LDAP bind) and `/auth/login` (OPAQUE) use the **same OPAQUE password hash** stored in SQLite
- The "Authentication protocol error" for `/auth/simple/login` was because the stored OPAQUE hash was corrupted (from a prior web UI password change)
- `force_ldap_user_pass_reset = "always"` causes password reset **every startup** and then exits (since `is_yes()` returns false for `Always`, server continues running after reset)
- After reset, pod should be restarted without the `always` flag

### Password Reset Results
- **Old password** (`0VFdWI9LXWugx8H0LpV5hePG`): ❌ rejected
- **New password** (`newpass123`): ✅ accepted, returns JWT
- **Form login** (`/auth/login`): ✅ 200 for both (SPA returns HTML)
- **user-invite auth**: ✅ now works with new password
- **GraphQL API**: ✅ works with new password token
