
## Role-enforcer Fix (2026-07-31)

**Problem:** Role-enforcer pod in `identity` ns was `ImagePullBackOff` with GHCR 403 Forbidden.

**Root causes:**
1. GHCR repo `yappingboy/role-enforcer` was empty (no images pushed)
2. Dockerfile builds dynamically-linked Go binary (needs libc in base image) — image had `alpine:3.19` base but layer was built without it
3. Pull secret used `yappingboy:GH_TOKEN` which doesn't have `read:packages` scope for GHCR

**Fix:**
1. Built Go binary with `CGO_ENABLED=0` (statically linked) to eliminate libc dependency
2. Pushed image to GHCR using Python requests (monolithic blob upload via GHCR registry API with `x-access-token` PAT format)
3. Updated `ghcr-credentials` secret in `identity` ns to use `x-access-token:GH_TOKEN` format
4. Pod restarted and is now `1/1 Running`

**Note:** There's a TLS cert verification warning for Keycloak (`x509: certificate signed by unknown authority`). The service is functional but may need the Keycloak CA cert mounted or `INSECURE_SKIP_VERIFY` config.


## user-invite GHCR Build Fixed (2026-07-31)

- **Root cause**: Multiple issues with GHCR auth secrets:
  1. Token expired — rotated to `.git-creds` token `GH_TOKEN`
  2. SOPS encrypted `config.json` as parsed YAML map — fixed by using JSON input type with `sops --encrypt --input-type json --output-type json`
  3. SOPS encrypted `.dockerconfigjson` in `stringData` — Kubernetes tried to base64-decode the SOPS-encrypted value. Fixed by using `data:` field (base64-encoded) instead of `stringData:`
  4. Wrong secret type `Opaque` vs `kubernetes.io/dockerconfigjson` — fixed to use correct type

- **SOPS encryption patterns**:
  - `secret-ghcr-toolbox.yaml`: JSON input, `--encrypted-regex '^(data|stringData)$'`, outputs as single-line JSON
  - `secret-ghcr-identity.yaml`: YAML input, `--encrypted-regex '^(data|stringData)$'`, uses `data:` field with base64-encoded value

- **Kaniko job**: Manually created (not CronJob) — manifest in `flux/apps/user-invite/kaniko-build.yaml`
- **New image**: `ghcr.io/yappingboy/becklab-user-invite:latest` — tag updated to timestamp for cache-busting
- **Deployment**: Running healthy on `ghcr.io/yappingboy/becklab-user-invite:v4.1785463096`

- **Rule**: Never manually patch secrets with `kubectl apply` or `kubectl patch`. Always fix the SOPS-encrypted manifest in the repo, commit, push, and let Flux apply. Manual patches cause drift detection failures and mean you have to manually reapply every fix.
- **Rule**: Verify new tokens are valid before putting them in secrets.
